# te-audit · TE 注释核查链

> 先校准字段语义，再用三类互不通气的证据交叉，最后给每一条元件一个**可归因**的登记。

不重新注释、不建库、不训练模型。只做一件事：**告诉你这份注释的哪些数字不能信，以及为什么。**

纯 Python 标准库，零第三方依赖。

**它不是什么**：不是注释流程，不是评估器（不打 F1），不是数据库。它读一份已经跑完的
注释，输出一份"哪里站不住"的清单。

---

## 30 秒看懂它在查什么

真实输出（水稻 Chr1+Chr12，420 条结构 LTR）：

```
C7 LTR 两套坐标是否自洽（repeat_region 含 TSD，分类行不含）
  可判 420 条   自洽 415 = 98.8%（判据 Δstart = Δend = len(tsd)）
    (Δstart, Δend, len(tsd)) = (5, 5, 5) → 410 条
    (Δstart, Δend, len(tsd)) = (4, 4, 4) → 5 条
    (Δstart, Δend, len(tsd)) = (7, 5, 5) → 4 条
```

它在说的是：**同一个元件，在同一份文件里有两套坐标。**

| 行 | 坐标 | 含 TSD |
|---|---|---|
| `repeat_region` | 106517..118085 | 是 |
| `Gypsy_LTR_retrotransposon` | 106522..118080 | 否 |

差值恰好等于 `len(tsd)`。于是 **TSD 只能在父行上查，motif 只能在分类行上查**。
用错一套的后果是 98.8% 变成 0%，而且**程序不会报任何错**——它只会让你以为数据坏了。

这类"读错了不报错、只会让结论整体偏掉"的地方，本工具收了 **13 项**。

## 为什么需要它

TE 注释的现状是：检测工具很多且在快速迭代（EDTA、RepeatModeler2、HiTE、Earl Grey），
但**输出端的验收基本靠人**。2022 年的工具评测结论是"仍需大量人工 curation"；
Earl Grey 2024 自己列出了三大质量问题（碎片化、consensus 末端不全、库冗余），
但都在管线内部解决，不提供独立验收层。

现成工具分四档，都不落在"位点"上：

| 粒度 | 工具 | 问的问题 | 前置条件 |
|---|---|---|---|
| 库级 | HiTE `lib_evaluation`、TE_Bench | 这套库整体好不好（F1） | gold standard 库 |
| 注释级·大类 | TEtrimmer `TE_anno_benchmarker` | 六类上的碱基混淆矩阵 | 人工 curated `.out` |
| 家族级 | TEtrimmer 分级、Earl Grey `--curate`、MCHelper | 这条 consensus 对不对 | 指定家族 |
| 逐条人工 | TE-Aid | 画 4 张图给人看 | 人 |

**位点级有人做过，本项目不声称首创。** PolyA（2021）做逐碱基置信度与动态规划裁决，
Carey 等（2021）证明 subfamily 标签有 >10% 不可复现并主张报告不确定性。
差别只剩三条，逐项对照写在
[TE_case/方法学_与PolyA与Carey的判据逐项对照.md](TE_case/方法学_与PolyA与Carey的判据逐项对照.md)：

1. **跨来源、跨证据类型的登记**（PolyA 裁决的是同一个库内部的竞争）
2. **解析层作为评测前置**（前两者默认标签读入正确；而 `intact.gff3` 一个元件 6 行、语义反直觉）
3. **"判不了"要归因，不是给分数**（分数说 0.52，不会说"因为边界落在 TA 微卫星里"）

还有一条更硬的限制：**LTR 侧没有独立实现可比**。HiTE 的 LTR 结构判定与 EDTA 共用
LTR_retriever（`judge_LTR_transposons.py` → `run_LTR_retriever`；`EDTA.pl` L290 直接
`command -v LTR_retriever`），所以拿 HiTE 质检 EDTA 的 LTR 是**同源自证**。源码证据见
[TE_case/方法学_已有QC工具与自建基准的分工.md](TE_case/方法学_已有QC工具与自建基准的分工.md)。

## 快速开始

```bash
git clone https://github.com/Sean060114/te-audit
cd te-audit

# 文件级六项（C1-C6），只需要 EDTA 输出目录，零依赖
python te_check.py --edta-dir chr1_edta_out

# 加上结构级五项（C7-C11），需要基因组 FASTA
python te_check.py --edta-dir chr1_edta_out --fasta TAIR10.Chr1.fa --json report.json

# 测试
python test_te_check.py          # 106 条，约 4 秒
```

`chr1_edta_out/` 是仓库内保留的一份完整 EDTA 运行（TAIR10 Chr1，218 个元件），
用来保证"克隆下来就能跑"。没有 FASTA 时 C7-C11 会明确跳过，不静默略过。
基因组 FASTA 不入库（体积原因），获取方式见 [docs/维护记录.md](docs/维护记录.md) 第五节。

输出是分段的文本报告；`--json` 给结构化结果，`--strict` 在有严重问题时返回退出码 1。

## 复现

报告里每个数字都能从入库的 EDTA 输出重新算出来，并与仓库里的版本**逐字节比对**：

```bash
bash reproduce.sh                  # 六张台账 + 六数据集对比，约 70 秒，不需要 FASTA
bash reproduce.sh --with-reports   # 另加四份检查报告，需基因组 FASTA
```

2026-11-24 实测 **12/12 一致，0 项差异**。产物写进 `_repro/`，不覆盖入库文件；
退出码 0/1 可直接接 CI。改判据后跑一次，就知道六张台账变了没有。

数据来源、分步命令、以及**哪些东西复现不了**（Repbase 授权、Carey 的 λ 分布、
WSL 里的中间产物、模块 2 的硬编码路径）都写在
[docs/复现指南.md](docs/复现指南.md)。

## 十三项检查

### 文件级六项（只需 EDTA 输出目录）

| 编号 | 查什么 | 判据 |
|---|---|---|
| **C1** 字段可得性 | 哪一类别整类没有 `identity` | 逐类统计五个质控字段 |
| **C2** 结构长度异常 | 内部区过短的"完整元件" | 内部区 = 总长 − 2×臂长，< 100 bp 告警 |
| **C3** 反向重复质量 | 匹配率能否当保守性指标 | 右臂对 revcomp(左臂) ±10 bp 滑移取最大 |
| **C4** 注释↔分类器覆盖 | 元件是否都进过分类器 | 按超家族分层，不混算 `LTR/unknown` |
| **C5** 库层面跨类 | 建库时混入了别的类别 | `cls.tsv` 的 order 与库类型不符 |
| **C6** 一致性与域证据 | 高一致性但无蛋白域 | `ltr_identity ≥ 0.95` 且两处都无域证据 |

### 结构与语义七项（C7-C11 需 `--fasta`）

| 编号 | 查什么 | 判据 |
|---|---|---|
| **C7** 两套坐标 | 父行与分类行的坐标差是否等于 TSD 长度 | `Δstart = Δend = len(tsd)` |
| **C8** motif 位置 | `motif=` 前后 2 nt 是否在 LTR 末端 | 负链取 rc **且交叉**（小坐标端是它的 3′ 端） |
| **C9** TIR 坐标 | TIR 的 TSD 在元件外侧还是内侧 | 取元件**外部** L bp 比 `tsd=`（与 LTR 相反） |
| **C10** identity 虚高 | `identity=` 与两臂实测差多少 | 严格逐位对位（**不滑移**），差 ≥0.20 告警 |
| **C11** 长臂内侧外推 | 长臂的错配是否全挤在内侧 | 外侧 2/3 与内侧 1/3 错配率对比 |
| **C12** 近重复记录 | 同一元件被输出了两次 | 起止相差 ≤2 bp 且同类别 |
| **C13** 家族标签分散 | 同一家族在不同位点标签不同 | 按 `Name` 聚合，分真冲突/含未定/仅自主性 |

C7-C13 不计入退出码，汇总里单列"结构级提示"。它们输出的是**事实**，不是"文件有错"：
C9 的 100% 通过率说明不了什么，C11 的 75% 也不代表假阳性。

## 三个真实案例

### 一、97.6% 通过了，但某一类 100% 是错的

`motif` 校验的第一版报 97.6% 通过，看起来完全正常。但把**负链元件单独拎出来**，
5 条全部失败——因为 420 条里有 **406 条的正读与 rc 读同时成立**（末端 2 nt 常相同或
回文），把 5 条负链的错读整个掩盖了。修正后 98.8%。

> 一个 97% 的数字，可能把某类 100% 的缺陷藏得严严实实。判据要通过，得拿"预期会
> 失败的那一小组"去反查，而不是看总体通过率。

### 二、按标签统计，74% 支持对方；按编码量统计，对方错了

23 条元件 EDTA 说 LTR、MSU 说 DNA 转座子。按 MSU 的 `Note` 字段统计，74% 落在
"DNA 转座子"——看起来是 EDTA 错了。

但先跑一次标签审计：**同一家族 6,156 bp 的基因模型，在 `retrotransposon protein`
与 `transposon protein` 两种标签下各出现 11 次**。标签取决于它落在哪个位点，是噪声。

改看编码架构：该位点两条模型 CDS 合计 **9,228 bp**（单一 6 kb ORF，一个 72 bp 内含子）。
DNA 转座子的转座酶是 300–800 aa（1–2.5 kb），9 kb 是 gag-pol 的量级。
**结论反转：MSU 的重复标签错。**

### 三、判据说"判不了"，而且能说清为什么

"Pack-MULE 还是拼接假阳性"——原判据很干净：真 Pack-MULE 意味着元件里装的是捕获
副本，donor 应该还在基因组里；若该基因全基因组只有一份，就只能是边界画错了。

跑了基线才发现：**随机的同规模基因里，50% 本来就是单拷贝**。于是"元件外没有拷贝"
丝毫不反常，推理链断在第一步。**5 条一条都没判掉。**

这条判据被明确记为"不成立"，脚本留着但结论作废——比一个"看起来能跑"的判据有用。

## 设计原则

**一、先算结构，再看标签；两者冲突时信结构。**
项目里出现过三次"标签与结构相反"：`log10_chance` 的量纲（`lgamma` 是自然对数）、
`\bsine\b` 的词尾边界、6,156 bp 模型的双标签。三次都是结构对、标签错。

**二、用错口径不会报错，所以要显式检查口径。**
`intact.gff3` 里两套坐标、两种链方向约定（序列按基因组正向，而 `tsd=`/`motif=` 按
元件方向）、覆盖率必须用并集——这三处错了都只是数字偏掉，不产生任何异常。

**三、"判不了"要归因，不是给分数。**
C 集里再分"标签冲突 / 无第二来源 / 边界不可定位"——归因不同，下一步动作不同。
分数告诉你 0.52 不可信，但不会告诉你"因为边界落在 TA 微卫星里、换参数也定不下来"。

**四、不声称首创，不声称更准。**
没有 gold standard，准确率无从比较，只能说解决不同问题。硬约束是两条：Repbase 需
商业授权、Dfam 3.9 里没有任何水稻家族（经 API 逐项核实）。

## 已知限制

1. **判据只在 EDTA 的 `intact.gff3` 上校准过。** 它一个元件 6 行、字段语义反直觉，
   C7/C8 那类问题在 RepeatMasker `.out` 上根本不存在（格式固定）。换工具要重新校准。
2. **没有 gold standard，所以不裁决"谁对"。** 输出是"这一行能信到什么程度"，
   不是"这一行是错的"。
3. **LTR 侧没有独立实现可比。** HiTE 与 EDTA 共用 LTR_retriever，换工具换不出独立证据；
   TIR 侧是独立的（TIR-Learner vs itrsearch），但目前未跑通对比。
4. **只覆盖水稻两条染色体**（70.8 Mb = 18.9% 基因组），不能外推为"水稻基因组"。
5. **C7-C11 需要 FASTA**，且 gff 与 FASTA 的染色体名要能对上（`OsChr1` ↔ `Chr1`
   有内建解析，其他命名需自行统一）。
6. **`te-normalizer/` 不在 C1–C13 的调用链里。** 它是上游的口径工具（名字 → SO 名），
   而 `te_check.py` 自带一份九类映射，两份实现各自维护。两者靠
   `test_te_check.py` 的五条 SO 表对齐测试共用词表：SO 表换了、`ELEMENT_TYPES`
   写错了、或有新的元件类型没被登记，测试会失败而不是静默跳过。换工具词表时两处都要改。
