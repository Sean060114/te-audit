## 3. 四条判据的判决

### 3.1 C1「整类无 identity」—— ✅ 跨科成立（第 5 次复现）

水稻 **299 个 helitron 全部**无 identity 数值（299/299）。与 Chr1、col1m、alyrata、
水稻预飞完全一致。

五种数据、两个科（十字花科 + 禾本科）、基因组大小差 40 倍，出现的永远是同一个类别。
成因在**数据格式**而非物种：helitron 没有 TIR/TSD 结构字段，identity 只能来自库同源匹配，
而 EDTA 的 de novo 路径不产生该值。

**结论可直接写进方法学，不需要按物种设例外。**

### 3.2 C3「反向重复质量」—— ⚠ 原结论已修正，但方向不变

**预飞阶段的说法（已作废）**：三份数据的匹配率最小值都精确等于 0.8000，无一低于，
因此是"严格左截断"。

**全染色体数据推翻了"无一低于"这半句**：

| 统计 | 数值 |
|---|---:|
| TIR 元件总数 | 1,152 |
| 匹配率中位 | 0.8182 |
| 匹配率范围 | **0.6244 – 1.0000** |
| < 0.80 的元件 | **6 个（0.52%）** |
| 落在 [0.80, 0.90) | **1,146 个（99.48%）** |

那 6 个例外全部是**长臂**元件：

```
0.6244  臂长 408 bp  Mutator   39,586,040..39,588,004
0.6277  臂长 285 bp  Mutator   29,178,747..29,182,854
0.7133  臂长 150 bp  Mutator   38,708,497..38,709,383
0.7170  臂长  55 bp  Tc1/Mar  4,929,076..4,929,370
0.7228  臂长 103 bp  Mutator   37,694,047..37,696,711
```

**修正后的表述**：不是严格截断，而是**阈值造成的极端富集**。

TIR-Learner 的算法规定 **minimum similarity = 80%**、最小 TIR 长度 10 bp，
只输出 ≥80% 的候选。te_check 用自己的口径（±10 bp 滑移）重算，因此有 0.52% 能掉到 0.8 以下
——而且掉的都是长臂元件，因为长比对更难维持高相似度。

预飞 80 个样本里一个都没掉下去，是抽样效应（期望 0.4 个），不是规律。

**判决不变，且理由更强**：99.48% 的元件挤在 [0.80, 0.90) 这 0.1 宽的区间里，
这不可能是真实的保守性分布。四份数据中位数几乎相同（0.812 / 0.818 / 0.840 / 0.818），
**不是 TIR 保守性相近，是同一个软件的同一条阈值**。

**这个指标测的是 TIR-Learner 的参数，不具备区分物种或数据集的能力，不应作为质量判据输出。**
真正有判别力的是完美反向重复数（五份数据 0 / 1 / 0 / 0 / 1）与臂长分布本身。

### 3.3 C4「只有 LTR 可要求全覆盖」—— ⚠ 判据其实成立，是我前两版报告的分母算错了

**这一节推翻我前两版报告的核心结论。** 前两版说"C4 的绝对阈值被证伪"，
理由是 alyrata 只有 75%、水稻预飞只有 87.5%、四个数据点跨度 75%–100%。

分层之后发现：那两个低值全是假象。

`LTR_retrotransposon` 这个 SO 类型本身的含义就是"LTR 但超家族未知"，
TEsorter 无法为它定超家族，它不进分类表是**预期行为**。把这类元件混进分母算覆盖率，
等于把预期行为当成了缺陷。

按超家族分层后：

| 数据集 | 已定超家族 | 未定超家族 | 其他类 |
|---|---|---|---|
| Chr1（重跑） | **40/40 = 100%**（原报 40/41 = 97.6%） | 0/1 = 0% | 12/177 = 6.8% |
| col1m | **4/4 = 100%** | 无此类 | 1/65 = 1.5% |
| alyrata | **3/3 = 100%**（原报 3/4 = 75%） | 0/1 = 0% | 0/16 = 0% |
| 水稻 预飞 | **14/14 = 100%**（原报 14/16 = 87.5%） | 0/2 = 0% | 0/98 = 0% |
| 水稻 全量 | **187/198 = 94.4%** | 0/20 = 0% | 14/1451 = 1.0% |

**四份小数据的已定超家族覆盖率全部是 100%。** 之前算出的 97.6%、75% 和 87.5%，
分子分母里都混着 `LTR/unknown`——把它们剔掉之后，波动完全消失。

**判决：C4 的规则是对的，错的是我的分母。**

- 「已定超家族的 LTR 应接近全覆盖」——五份数据实测 100% / 100% / 100% / 100% / 94.4%，
  在小样本上严格成立，水稻全量才出现真实缺口
- 「未定超家族的 LTR 不进分类表」——预期行为，单独计数，不参与覆盖率
- **不存在"阈值该不该用"的问题**：只要分母正确，LTR 覆盖率就是一个稳定可靠的指标

我前两版"删掉阈值、改为逐元件核查"的建议方向对但理由错。
真正的修法是**分层**，而不是放弃阈值。

#### Chr1 重跑：一次事前预测的验证

这是本报告唯一一处**先写下预测、再跑数据核对**的地方，所以单独列出来。

上一版报告里 Chr1 是缺位的（`~/te_bench` 中找不到 `intact.gff3`），
只能引用旧值 40/41。当时我依据"其唯一缺失元件是 `LTR/unknown`"写下推论：

> 按现行分层判据，Chr1 应为 **40/40 = 100%**，待重跑确认。

重跑结果（TAIR10 Chr1，30,427,671 bp，参数与前四份一致，v2.2.2）：

| 指标 | 旧值（未分层） | 重跑实测 |
|---|---|---|
| intact 元件 | 218 | **218**（完全一致） |
| LTR 总数 | 41 | **41** |
| 已定超家族 LTR | 40/41 = 97.6% | **40/40 = 100%** |
| 未定超家族 | （未单独统计） | 0/1，唯一那一个是 `17528667..17536138 LTR/unknown` |

**一处必须说明的来源差异**：旧 Chr1 取自 EDTA 自带的 `share/EDTA/test/` 区段，
本次重跑用的是 Ensembl Plants release-57 的 `Arabidopsis_thaliana.TAIR10.dna.chromosome.1`
（30,427,671 bp，即 TAIR10 Chr1 的标准长度）。两者应当同源，且元件数 218、
LTR 41 完全吻合；但原始文件已不在，**无法证明两个输入逐字节相同**。
因此"完全相同"只落在计数层面，不能声称序列层面已核对。

**预测成立，且元件总数 218 与两版之前完全一致**——这说明旧数据本身没问题，
错的只是统计口径。重跑没有改变任何一个元件，只改变了它们被如何归类计数。

顺带确认了一件事：旧报告"40/41 = 97.6%"这个数字并非错误数据，
而是**在没有分层的情况下，把一个预期不分类的元件算成了缺失**。

#### Chr1 的定量 sanity check：8.96% 不是注释缺失

Chr1 总 TE 覆盖 **8.96%**（2,710,874 / 30,263,312 bp），初看低于
"拟南芥基因组约 20%" 的常见说法，需要排除"漏注释"的可能。
按 1 Mb 分箱后分布如下：

| 区间 | 覆盖 | 区间 | 覆盖 |
|---|---:|---|---:|
| 0–10 Mb（左臂） | 2.5–6.6% | 16–18 Mb | 24.1% → 17.9% |
| 10–12 Mb（过渡） | 10.0% → 16.0% | 18–22 Mb（右臂） | 8.6% → 3.7% |
| **13–15 Mb（着丝粒）** | **34.6% / 36.5% / 34.4%** | 22–30 Mb（右臂末端） | 1.5–5.7% |

这是拟南芥 Chr1 的标准结构：**基因密集的臂区 2–6%，着丝粒异染色质 34–36%**。
把臂区（约 25 Mb × 4.5%）与着丝粒（约 5 Mb × 30%）按长度加权，
正好得到 8.96%。**所以这个数字是染色体构成的结果，不是召回率问题。**

顺带一个交叉验证：分箱求和 = 2,710,874 bp，与 `TEanno.sum` 的
`Total interspersed` 逐 bp 相等，说明两个统计路径自洽。

需要注意的是，这只能排除"整体漏注释"，**不能**排除局部漏注释；
且第 5.1 节的 RepeatMasker 兼容缺陷依然存在，本份数据仍不宜用于评估召回率。


#### 水稻全量那 11 个真实缺失

94.4% 的缺口来自 11 个已定 Gypsy（198 个里的 5.6%），结构证据分布：

| strand_evidence | 个数 |
|---|---:|
| PBS, PPT | 8 |
| domain, PBS | 2 |
| domain, PBS, PPT | 1 |

这些元件结构完整、超家族已定，却从未进入分类器——**这才是需要逐个核查的对象**，
明细见 `rice/full_report.json` 的 `C4_not_classified`。

#### 为什么小样本看不出来

alyrata 只有 4 个 LTR，其中 1 个是 `LTR/unknown`。分母 4、分子 3，得出 75%，
看起来像"每四个 LTR 就有一个被丢掉"。分层后是 3/3 = 100%，缺口为零。

**4 个样本算百分比本身就没有意义**，而分母里再混进类别错误的元件，
就足以让我得出一个方向性错误的结论，并且连续两版报告都在重复它。

水稻 218 个 LTR 的价值就在这里：它让"两类完全不同的缺失"从统计噪声里分离出来。

### 3.4 C6「高一致性但缺域证据」—— ✅ 判据成立，水稻给出 23 例

修正实现缺陷后（见第 6 节），水稻检出 **23 个** C6 元件，全部是 `ltr_identity` 0.957–1.000
但既无分类表域证据、`strand_evidence` 里也没有 domain 的元件。

这是四份数据里样本最大的一次（Chr1 1 个、alyrata 1 个、col1m 0 个、水稻 23 个），
说明这个现象在高 TE 含量基因组里远比小样本显示的普遍。

逐条明细见 `rice/full_report.json` 的 `C6_ltr_conflict`。

## 4. C2 与 C5（附带观察）

**C2 在全量数据上才显现。** 预飞 3 Mb 是 0 个，全量 24 个内部区 < 100 bp，
最短仅 **11 bp**（`23,900,403..23,900,483`，总长 81 bp、臂长 35 bp）。

内部区 11 bp 在生物学上不可能是完整转座子的内部序列，这些更接近 MITE 或假阳性。
**这印证了 C2 的判据有效，同时也说明小样本会漏掉它**——预飞阶段的"0 个"是抽样不足，
不是水稻没有短元件。

**C5 随基因组规模放大。** 31 条跨类（Helitron→LTR 17、TIR→LTR 5、Helitron→TIR 4、
Helitron→LINE 4、TIR→LINE 1），与 Chr1 的 15 条同量级，符合"库越大混入越多"的预期。
这个指标不适合做跨数据集稳定性比较，只适合同一数据集内的质量记录。

## 5. 运行环境问题

### 5.1 RepeatMasker 库兼容（复现，但未损害结果）

```
cp: cannot stat '.../RepeatMasker/Libraries//general.working/*': No such file or directory
Warning: No sequences were masked
```

EDTA v2.2.2 期望旧版 RepeatMasker 的 `general.working` 工作库，而环境是新版（用 Dfam.h5）。
**前三份数据与水稻预飞都未出现此问题**，全染色体这次稳定复现。

**影响评估：没有损害注释质量。** 依据是第 2 节的定量结果——37.64% 的总覆盖与家族排序
都与水稻已知特征吻合。如果 filter 阶段的失效严重到影响建库，这个数字会明显偏离。

### 5.2 预飞的 stat 错误未复现

预飞时报 `ERROR: TE annotation stats results not found in ....EDTA.TE.fa.stat!`，
`TEanno.sum` 的 `Repeat Stats` 段为空。**全染色体没有这个问题**，`Repeat Stats` 正常列出
每个 TE 的 mask 情况，并生成了 `.stat.all.sum` / `.nested.sum` / `.redun.sum` 三个文件。

推测是预飞的 3 Mb 片段太小、某步未触发。**结论：该错误与数据规模相关，不具普遍性。**

### 5.3 LTR 阶段失败与 `.mod.mod` 前缀（**成因待定**，此前两版归因均已撤回）

**这一节我写错过两次，现在只记录可复现的事实和已排除的路径，不再给结论。**

现象（四个基因组稳定复现：col1m、alyrata、水稻、Chr1）：

```
ERROR: Raw LTR results not found in X.fa.mod.EDTA.raw/X.fa.mod.LTR.raw.fa
修复：复制 9 个文件（X.mod.mod.* → X.mod.*）
```

`pass.list` / `defalse` / `LTRlib.fa` 等 LTR_retriever 产物全在 `X.fa.mod.mod.*`
前缀下，而 EDTA 按 `X.fa.mod.*` 查找。改名后建库即通过，LTRlib 完整
（水稻 913,250 B，Chr1 238,846 B）。

#### 两次被推翻的归因

| 版本 | 说法 | 为什么不成立 |
|---|---|---|
| 一 | `LTR_retriever.py:70` 的 `glob(genome+'.mod.*')` 拼写缺陷，重复追加 `.mod` | 无源码支持，纯属从文件名倒推 |
| 二 | EDTA issue #599：序列名超过 **rmblastn 约 50 字符上限**，触发 seqid 编码分支 | **本场景 seqid 是 `>Chr1` / `>OsChr1`，仅 4–6 字符**，不可能超长；而两个基因组都稳定复现。长头解释无法适用 |

第二条尤其要记住：issue #599 的原文我核对过，维护者确实是这么说的，
但**那个解释针对的是另一条触发路径**。issue 描述的症状和我们一样，
成因不一定一样——这正是"症状吻合就认领别人的根因"的危险。

#### 已排除的路径（对着源码逐行核对）

| 文件 | 位置 | 排除理由 |
|---|---|---|
| `EDTA.pl` v2.2.2 | 365–398 | 有 `if ($id_len > 13)` 截断分支，但 `$id_len` 取自 `grep '>'`（仅表头行），Chr1 得 4，不进分支；且进入该段时 `$genome` 是 `X.fa`，只能产生单层 `.mod` |
| `EDTA_raw.pl` v2.2.2 | 347–389 | 同一套 13 字符逻辑，但 EDTA.pl 以 `--convert_seq_name 0` 调用，**整段被跳过** |
| `LTR_retriever` v2.9.9 | 全文 | 仅 6 处 `.mod`，全部位于 `$id_len > 13` 分支内，条件同样不满足 |

> 顺带排除一个我以为的 bug：`grep \>` 看着像词边界会匹配所有行，
> 但在 Perl 反引号里反斜杠被 shell 吃掉，grep 收到的是字面量 `>`，
> 所以只匹配表头——**这个"bug"不存在**，不能用来解释现象。

#### 剩余最可疑、但尚未验证的一条

日志里那两次 `Warning: No sequences were masked` 与
`cp: cannot stat '.../RepeatMasker/Libraries/general.working/*'` 紧挨着出现。
如果 LTR_retriever 内置的 RepeatMasker 步骤把**已经 mask 过**的 `X.fa.mod`
当成未 mask 输入再 mask 一次，它的输出正好就是 `X.fa.mod.mod`。

**这条只是假设。** 验证只需在 WSL 里跑一行：

```bash
grep -n '\.mod' "$CONDA_PREFIX/share/LTR_retriever/LTR_retriever" | head -20
```

若出现 13 字符分支之外的 `.mod` 赋值（尤其是 RepeatMasker 附近），假设成立。
配合看 `ls ~/te_bench_chr1/*.mod*` 里是否存在 `X.fa.mod.out` 一类的 masking 产物。

#### 因此：不要提 issue，也不要宣称升级能根治

- **不提 issue**：重复报告无价值，且我们连成因都没确认。
- **不能宣称 v2.3.0 能根治**：我此前写过"升级即解决"，这个说法现在**没有依据**。
  维护者的 v2.3.0 修复针对的是长头触发的 seqid 编码，与本场景是否同因未验证。

**应急手段（已实证有效，四个基因组）**：`run_bench_rice.sh` 内置改名修复，
把 `X.fa.mod.mod.*` 复制成 `X.fa.mod.*`。这些文件只含序列 ID 与坐标，
不含文件名，改名不改语义。

**一个仍未验证的推论**：若该命名异常在 LTR 阶段留下残缺，可能影响下游 TEsorter
输入，进而解释第 3.3 节那 11 个"已定 Gypsy 却不进分类表"的元件。
**在成因未定之前，这个推论只能挂着，不能用升级来检验。**

## 6. 对 te_check 的三条修订

1. **C6**（预飞阶段修）：域证据改为「分类表 `domains` ∪ intact.gff3 的 `strand_evidence`」。
   修掉"文件里写着有域、工具说缺域"的自相矛盾。

   不是"低于阈值的不会出现"，而是"99.5% 挤在阈值之上 0.1 宽的区间内"。
3. **C4**（本轮新增，已实现）：按超家族分层报告覆盖率，把 `LTR/unknown` 的预期内缺失

   `bench_multi.py` 同步改为分层展示，并新增 `asg_*` / `una_*` 指标。
   Chr1 回归基线的 `severe` 因此从 5 降到 4（那个缺失元件是 `LTR/unknown`）。

测试 69 → 73 条，全过。

## 7. 局限

1. ~~**Chr1 数据集本轮缺位。**~~ **已解决。** 原 `~/te_bench` 中找不到 Chr1 的
   `intact.gff3`，`bench_archive/` 只收录了 col1m 与 alyrata，Chr1 只能引用旧值。
   现已用 `ref/TAIR10.Chr1.fa`（30,427,671 bp）重跑，参数与前四份完全一致（v2.2.2）：
   218 个元件、41 个 LTR、已定超家族 **40/40 = 100%**，
   与事前预测一致（见第 3.3 节）。五份数据的分层对比现已完整
   （`TE_case/bench_five.tsv`）。
   **重跑代价**：47 分钟（18:51–19:37），产出 `chr1_edta_out/`。
2. **只有一个水稻品种、一条染色体。** 未检验籼稻/粳稻差异，也未检验其他染色体。
3. **运行环境存在 RepeatMasker 兼容缺陷**（第 5.1 节）。虽然定量结果正常，
   但这份数据不宜用于评估 EDTA 的召回率，也不宜与其他 EDTA 版本横向比较。
4. **`--species Rice` 的作用未做对照实验。** 我们按源码判断它只影响 TIR 候选鉴定，
   但没有跑 `--species others` 的水稻对照组来实测差异。
5. **C4 的分层结论现有五份数据支持，但仍都是 EDTA 环境下的观察。**
   `LTR/unknown` 共 24 个（Chr1 1、alyrata 1、水稻预飞 2、水稻全量 20），
   **无一进入分类表**；col1m 则没有此类元件。这比单一数据集的证据强得多，
   但"未定超家族一律不分类"仍是从工具行为归纳出来的，不是从 TEsorter 源码推出的。
6. **`--species others` 跑 Chr1 的成功，不能替代水稻的对照组。** Chr1 用 `others`、
   水稻用 `Rice`，两者既有物种差异也有参数差异，不能互相验证参数效果。
7. **`.mod.mod` 的成因仍未确定**（第 5.3 节）。我先后给过两版解释，都被源码推翻，
   现在只保留"现象可复现 + 改名修复有效"。这不是判据问题（四个基因组改名后
   建库都正常），但它意味着**我们对该流程的理解仍有一处空白**，
   而这处空白恰好可能关联水稻那 11 个缺失元件。

## 8. 一句话结论

水稻**确认了 C1 的跨科可移植性**（第五次复现，两个科），**修正了 C3 的表述**
（不是严格截断，但 99.5% 的富集仍是阈值投影，该指标无判别力），
并且**发现 C4 的判据本身没错——错的是我前两版报告的分母**。

把 `LTR/unknown` 从分母里剔掉之后，四份小数据的 LTR 覆盖率全部回到 100%，
那个被我当成"阈值不成立"证据的 75%，其实是"4 个样本里有 1 个属于预期不分类"。

**最有价值的不是判据通过，而是换第四个数据集时发现：**
**我用来反驳判据的证据，本身是个统计假象——而且我在两版报告里重复用了它。**

水稻 218 个 LTR 才让这个错误显形。4 个样本算出来的百分比，不该用来推翻一条规则。

补跑 Chr1 之后多了一条方法学结论：**改判据之前先检查分母**。
同一个 218 个元件的数据集，只换统计口径，覆盖率就从 97.6% 变成 100%，
而元件本身一个都没变。判据说"有缺失"时，先问是谁被算进了缺口。
