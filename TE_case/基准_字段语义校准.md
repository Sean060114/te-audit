# 基准字段语义校准：EDTA 结构法 LTR 元件

> 2026-11-23。本文是「建基准」的第 1 步：在建 A/B/C 三套参照集之前，先把
> `intact.gff3` 里每个字段的含义、坐标约定钉死。**语义没钉死之前，任何复算率
> 都是噪声。**

## 一、为什么必须先做这一步

第一次按直觉复算 `tsd=` 时，用了两种最自然的约定，命中率分别只有 **8.1%** 和
**23.8%**。看起来像"字段不可靠"，实际是**约定错了三处**：元件行混进了子特征行、
负链未取反向互补、`motif` 被当成连续 4 碱基搜。三处修正后，同一批数据的复算率
是 **99.0%**。

这就是本节存在的理由：**同一份数据，约定错时 8%，约定对时 99%**。先把约定写下来。

## 二、五条语义（据源码确认）

源码：EDTA v2.2.2 `bin/make_gff3.pl`（tag `v2.2.2`，commit `911304b`）与
LTR_retriever `bin/make_gff3.pl`（master，v2.3.5 同期）。

| # | 语义 | 依据 |
|---|---|---|
| 1 | 坐标是 **1-based 闭区间** | `print GFF "$chr\t...\t$element_start\t$element_end"`，取值直接来自 pass.list 的 `lTSD`/`rTSD` 坐标 |
| 2 | `repeat_region` 的起止 = **5′TSD 第一个碱基 … 3′TSD 最后一个碱基**，TSD **含在**元件坐标内；仅当 `tsd=NA` 时退化为左右 LTR 起止 | `$element_start=(split /\s+/, $lTSD)[0]; $element_end=(split /\s+/, $rTSD)[1];` 及随后的 `if ($TSD eq "NA")` 分支 |
| 3 | `tsd=` 按**元件方向**书写：负链元件需反向互补后再与基因组比对 | 负链按元件方向输出，实测 217 条负链全部需 rc 才成立 |
| 4 | `motif=TGCA` 是**LTR 末端基序**，拆成「前 2 nt + 后 2 nt」，分别落在 5′LTR 起点与 3′LTR 终点，**不是**边界处连续的 4 个碱基 | `motif` 直接取自 pass.list 的 `motif:` 字段；实测 97.6% 满足拆分规则 |
| 5 | 一个 LTR 元件在 `intact.gff3` 里占 **6 行**（`repeat_region` / `lTSD` / `lLTR` / `LTRRT` / `rLTR` / `rTSD`），**只有 `repeat_region` 行代表元件** | 420 元件 × 6 = 2,520 行，与文件实际行数吻合 |

第 5 条是最容易踩的坑：按 `classification=LTR/*` 统计会得到 2,520，按元件统计是
**420**——两者相差 6 倍，而报告里此前出现的「420 条」正是元件数。

## 三、复算结果（Chr1+Chr12，双条运行）

命令见第五节。输出：

| 指标 | 结果 |
|---|---:|
| LTR 元件（`repeat_region` 行） | **420** |
| 5′ TSD 与序列完全一致 | **416 / 420（99.0%）** |
| 3′ TSD 与序列完全一致 | **420 / 420（100%）** |
| 两侧同时成立 | 416 / 420（99.0%） |
| 末端基序（motif 前 2 + 后 2） | **410 / 420（97.6%）** |
| `ltr_identity` 字段值（中位 / 最小） | 0.9927 / 0.9199（**未复算**，见第四节） |

**结论：结构自证这一证据位，在这 420 条元件上成立。** 它不再依赖"EDTA 说它对"，
而是能被基因组序列独立重算。

**跨物种复核**（拟南芥 TAIR10 Chr1，同一脚本不改一行）：41 条元件，5′ TSD 95.1%、
3′ TSD 100%、motif 87.8%。motif 偏低的原因是部分元件的末端基序不是 `TGCA`
（存在 `TGTG…CACA` 一类），提示该检查应按 motif 字段本身而非固定 `TGCA` 判断——
本脚本已是这么做的，低值属真实分布，不是脚本缺陷。

## 四、4 条例外的性质

5′ 侧不一致的 4 条，全部是**低复杂度 TSD**（`ATATA`、`GAGAG`、`TATAT`），与字段值
差 1–2 bp，而 3′ 侧 100% 成立。合理解释是：字段记录的是某一侧拷贝或两者的一致序列，
低复杂度位点上定位会偏 1–2 bp。这属于**坐标级不确定性**，不是数据错误，在基准里应
标注为「TSD 长度可变/低复杂度」而不是「不通过」。

## 五、两个未闭合项

**1. `ltr_identity` 无法独立复算。** 复算它需要左右 LTR 各自的起止坐标，而
LTR_retriever 的 `*.pass.list` 未随产物回传（`EDTA.raw/LTR/` 下只有 TEsorter 的
分类 tsv）。目前的 0.9927 是**引用 EDTA 的字段值**，不能算自证。
→ 下次运行请保留 `$genome.EDTA.raw/LTR/*.pass.list`，或直接保留整个 `.raw/LTR/` 目录。

**2. 版本疑点。** 本项目的产物里含 `strand_evidence=domain,PBS,PPT` 字段，而该字段
**不在 EDTA v2.2.2 源码中**（`git grep strand_evidence` 在 tag v2.2.2 与 master v2.3.5
均为空），它来自 LTR_retriever 的 `bin/make_gff3.pl`。EDTA 依赖独立的 LTR_retriever
安装，版本未记录在 `RUN_INFO.txt` 里。
→ 这属于可复现性缺陷：**六份数据必须确认是同一套 EDTA + LTR_retriever 版本跑出来的**，
否则跨数据集比较不成立。建议下次在 `RUN_INFO.txt` 里补 EDTA 与 LTR_retriever 的版本号
和 `conda list` 快照。

## 六、复现

```bash
python TE_case/verify_ltr_structure.py \
  --gff rice/edta_out_multi/Oryza_sativa.Chr1_Chr12.fa.mod.EDTA.intact.gff3 \
  --fasta rice/Oryza_sativa.Chr1.fa rice/Oryza_sativa.Chr12.fa
```

脚本只依赖标准库，读 FASTA 与 `repeat_region` 行，输出上表各项计数。
